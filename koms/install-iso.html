Official install One-stick install MCP AI clients

One stick, a few questions

An ISO that boots on the machine you want to install on, asks four questions, fetches the current Home Assistant OS image itself and writes it to the disk you pick. No adapter, no second operating system, no commands.

It exists because the official route needs either an adapter and a second computer, or a live Ubuntu session first. This needs a USB stick and about twenty minutes. The installer runs entirely from the stick, in fourteen languages, with the matching keyboard layout for each.

What you need

  • The same 64-bit PC, 2 GB of RAM and 32 GB of storage as before, with UEFI boot and Secure Boot switched off.
  • A USB stick, 8 GB or more. It is erased when you write the ISO to it.
  • Internet access during the install, over cable or Wi-Fi. Unless you already have an image file — see below.

The steps

  1. Download the ISO

    From the latest release, take the file ending in -amd64.iso and its .sha256 companion. About 470 MB.

    Checking it takes ten seconds and catches a download that went wrong: on Linux or macOS, sha256sum -c haos-isoinstall-*.iso.sha256 in the folder you saved both files in. On Windows, certutil -hashfile haos-isoinstall-v1.1.0-amd64.iso SHA256 and compare the line it prints with the one inside the .sha256 file.

  2. Write the ISO to the stick

    Etcher or Rufus, the same way as any other ISO. Not by copying the file onto the stick — a copied file cannot boot, because the stick also needs a boot sector and a filesystem the firmware understands.

    In Rufus, choose DD mode if it offers a choice. In Etcher there is nothing to choose.

  3. Two BIOS settings

    UEFI boot on, Secure Boot off. Enter the firmware with F2 or Del, change both, save. SATA mode should be AHCI if the machine offers a choice between that and RAID.

  4. Boot the stick and answer four questions

    The installer starts on its own. Boot text scrolls for a moment; that is normal. Then:

    • Language — fourteen, each with its own keyboard layout.
    • Where the image comes from — download the current version, or use one you already have. This is asked before anything touches the network.
    • Network — automatic over Ethernet, otherwise pick your Wi-Fi and type the password.
    • Disk — the size, model and current contents of each disk are shown. You must type YES to confirm; anything else stops and nothing is written.

    Then it downloads, verifies, erases and writes, each with its own progress bar. The image is checked before the disk is touched, so a network failure leaves your disk as it was, and an interrupted download resumes rather than starting over.

  5. Say yes to the read-back check

    After writing, it offers to read the bytes back off the disk and compare their hash with the image it wrote. One to three minutes, and it is the difference between finding a worn SSD or a loose cable now and finding it as a machine that boots to a black screen. Declining is allowed and changes nothing else.

  6. Remove the stick and let it reboot

    The installer runs from memory, so the stick is not needed once the write is done. The machine reboots into Home Assistant. From another computer, open http://homeassistant.local:8123 and create the owner account.

Using an image you already have

If the machine has no network, or you would rather not download half a gigabyte twice, put the .img.xz file on a USB stick and choose the second option at the image question. The stick is mounted read-only and the file is checked before anything is written, so an incomplete or corrupt image is refused instead of copied.

Nothing is downloaded in that mode and nothing on your stick is changed or deleted — the installer only ever reads from it.

Short on memory?

The image is held outside the target disk until it has been checked, which needs a few hundred megabytes of free memory. On a 2 GB machine the installer says so, asks for a spare USB stick to stage the file on, and carries on from there. It never uses its own stick for this — that one is read-only, and it is your way back in if something fails.

What it does not do

No dual boot: the disk you choose is the disk Home Assistant gets. No ARM or Raspberry Pi — the ISO is for ordinary 64-bit PCs. And it does not configure Home Assistant for you; it hands over a freshly installed system and reboots into it, which is exactly where the official route ends too.

If it doesn't work

The stick does not appear in the boot menu

Secure Boot is still on, or the stick was written in a mode the firmware cannot read. Turn Secure Boot off; if that is not it, rewrite the stick in Rufus with DD mode and try again. Some machines also need USB boot enabled explicitly.

It cannot find the network

Plug in a cable. Wi-Fi needs the driver for your card to be present in the installer; Ethernet almost always works. If you have an image file on a stick, the offline option skips the network question entirely.

It refuses the image file

The file is not a complete .img.xz: an interrupted copy, a truncated download, or a file renamed to look right. Re-copy it, or let the installer download the current version instead.

The disk you want is not listed

The installer deliberately hides the stick it is running from, and any disk that is part of the running system. If an internal disk is missing entirely, it is usually a controller setting — check AHCI and that the disk is visible in the firmware at all.
