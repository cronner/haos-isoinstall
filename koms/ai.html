Connect an AI client

One URL, one login, and your house is a tool the AI can use. Below is what to paste where for the clients people actually use — and the difference between the ones that run on your machine and the ones that run in a data centre.

Prerequisite: the MCP server is switched on and you have its URL — that is the previous page. Everything here assumes http://homeassistant.local:8123/api/mcp for local clients, and an HTTPS address for cloud ones.

Claude

Claude reaches MCP servers from its own cloud, including when you use the desktop app, so Home Assistant must be reachable from the internet. If you have not set that up, do that step first.

  1. Open the connector form

    On claude.ai: the Claude connectors page, then Add → Add custom connector. In Claude Desktop: the same thing under Settings → Connectors.

  2. Name it and paste the URL

    Name: Home Assistant. MCP Server URL: your HTTPS MCP address. Add it.

  3. Sign in

    Authentication: Sign in now. OAuth client: Use Claude's published identity. Then Connect on the connector page, and log in to Home Assistant in the window that opens.

In a chat, enable the Home Assistant tools. Claude asks before calling any of them, which is the behaviour you want: you see the request, you approve it.

ChatGPT

  1. Add a custom MCP server

    On chatgpt.com, open the plugins page and choose Add → Add custom MCP server. In the desktop app it sits under Settings → Plugins. Depending on your rollout the same page is labelled Apps or Connectors.

  2. Fill in two fields

    Name: Home Assistant. Connection: your HTTPS MCP URL. Authentication: OAuth. Confirm that you understand, then create it as a plugin.

  3. Connect and log in

    ChatGPT offers Connect Home Assistant → Continue; sign in to Home Assistant there. The account needs to be an administrator if the integration still requires one.

ChatGPT will not take a token

Custom MCP servers in ChatGPT authenticate with OAuth or not at all — there is no field for a static bearer token. That is fine here, because Home Assistant speaks OAuth. It only becomes a problem with a third-party MCP server that expects a header.

Claude Code

A terminal agent, so it runs on your machine — but it connects over HTTPS only, so it still needs your external address rather than homeassistant.local. 

claude mcp add --transport http home-assistant https://your-address/api/mcp
claude mcp login home-assistant

The second command opens your browser for the Home Assistant login. Add --scope user to make it available in every project instead of only the current one.

Codex CLI

Runs locally and speaks plain HTTP, so the local address works. 

codex mcp add homeassistant --url http://homeassistant.local:8123/api/mcp

It opens Home Assistant in your browser for the login. The entry lands in ~/.codex/config.toml as an [mcp_servers.homeassistant] block with a url line, which is all it needs.

opencode

opencode mcp add home-assistant --url http://homeassistant.local:8123/api/mcp
opencode mcp auth home-assistant

The second command is the OAuth login. Without it the server shows up but every call fails with an authentication error. The entry is written to opencode.json under mcp as {"type": "remote", "url": "..."}; opencode mcp list shows whether it is connected.

Gemini CLI

gemini mcp add --transport http home-assistant http://homeassistant.local:8123/api/mcp

If it asks for authentication, let it run the browser flow. In ~/.gemini/settings.json the same server appears under mcpServers with an httpUrl key.

Editors: Cursor, VS Code, Cline

All three take a JSON entry and run locally. None of them need a token for Home Assistant: give them the URL and sign in when the editor offers it.

Cursor — ~/.cursor/mcp.json:

{
  "mcpServers": {
    "home-assistant": {
      "url": "http://homeassistant.local:8123/api/mcp"
    }
  }
}

VS Code — .vscode/mcp.json in the project, or your user profile:

{
  "servers": {
    "home-assistant": {
      "type": "http",
      "url": "http://homeassistant.local:8123/api/mcp"
    }
  }
}

Cline — cline_mcp_settings.json:

{
  "mcpServers": {
    "home-assistant": {
      "type": "streamableHttp",
      "url": "http://homeassistant.local:8123/api/mcp"
    }
  }
}

Claude Desktop's own config file is the odd one out: it only starts local programs, so a remote URL written there is ignored. Use the in-app connector described above instead.

Or keep the AI inside Home Assistant

MCP is for bringing an outside AI in. The other direction is simpler and needs no MCP at all: Home Assistant has conversation agents of its own, and they can control the house directly.

IntegrationWhat it gives you
AnthropicA Claude-powered conversation agent and AI task, with optional web search and code execution.
OpenAIConversation, AI task, speech to text and text to speech from OpenAI's own endpoint.
Google GeminiA Gemini conversation agent; the integration is titled Google Gemini even where older pages call it Google Generative AI.
OllamaModels running on your own hardware. Controlling the house is experimental here, and fewer than 25 exposed entities is the recommended ceiling.

All four are added under Settings → Devices & services → Add Integration. Pick your agent in the Assist settings, and it inherits the exposure list you already have.

What to try first

Start with questions rather than orders, because they show you what the model can see:

  • "Which windows are open?"
  • "What is the temperature in the bedroom, and is the heating on?"
  • "Turn off the lights in the living room."
  • "Is anything left on that shouldn't be?"

If a device is invisible to the AI, it is almost always missing from the exposure list — not broken. Check the exposure step before you go looking for a bug.

Two things to keep in mind

An AI that can switch things can also switch the wrong thing: names like "office light" are ambiguous in a house with three of them. Give entities clear names before you hand them over. And keep the confirmation prompt on in the client — an agent that acts without asking is one bad sentence away from an open door at 3 a.m.

Commands follow Home Assistant's MCP server documentation, which keeps a client list of its own. Client menus move around; if a label here no longer matches what you see, the vendor's own page is the place to check.
