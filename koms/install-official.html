The official install

Home Assistant OS has no installer of its own: you write a finished disk image to the disk the machine will boot from, and that is the install. This is the route Home Assistant documents, done carefully.

What you need

  • A dedicated 64-bit PC — mini-PC, old desktop, thin client. The whole machine becomes Home Assistant.
  • UEFI boot, which nearly everything made in the last ten years has. Secure Boot must be off.
  • 2 GB of RAM minimum, 4 GB comfortable. 32 GB of storage is enough to start.
  • A USB stick, 8 GB or more, that can be erased.
  • Ethernet is strongly recommended for the first start.
This erases the target disk

The image is a complete disk, so writing it destroys everything on the disk it lands on — including any other operating system. There is no dual boot and no undo. Move your files off first.

The steps

  1. Get the image

    On home-assistant.io/installation, choose Generic x86-64. You get a file ending in .img.xz, roughly half a gigabyte. That compressed file is the whole operating system.

    Keep it as it is — do not unpack it, and do not open it. Etcher and the other tools read compressed images directly.

  2. Write it to the disk the machine will boot from

    There are two ways to do this, and which one you can use depends on whether you can unplug the target disk from the machine.

    If the target disk is easy to reach — an SSD, an M.2 drive, or a small computer you can open — take it out, connect it to your normal computer through a USB adapter, and write the image to it with Etcher. Pick the image, pick the disk, confirm. Etcher shows the target disk by size and name, so check that it is the right one before you press the button. When it is done, put the disk back.

    If the disk cannot come out — a laptop, or a case you would rather not open — Home Assistant's own documentation recommends booting a live Ubuntu from a USB stick on the target machine, downloading the image there, and restoring it onto the internal disk with Ubuntu's Disks utility (three-dot menu, Restore Disk Image). It works, but it is a second operating system and a second set of decisions before you have even started.

    That gap is what the installer fills

    The one-stick installer boots the target machine, downloads the current image itself and writes it to the disk you choose. One stick, no adapter, no second system.

  3. Two BIOS settings

    Start the machine and press the key that opens the firmware setup — usually F2, sometimes Del, F1 or F10. You need two things:

    • UEFI boot mode: on. If there is a choice between Legacy/CSM and UEFI, choose UEFI.
    • Secure Boot: off. Home Assistant OS is not signed for it, and the machine will refuse to boot with it on.

    Save and exit. While you are here, check that booting from USB is allowed — you may need it.

  4. Start it and leave it alone

    With the disk in place and the USB stick out, power on. The screen fills with boot text for a minute or two, then settles into a Home Assistant console with a login prompt and, usually, an IP address.

    Nothing is asked of you. The first start prepares the system and can take 15 to 20 minutes — on slow storage, longer. Resist the urge to reboot it; progress is happening even when the screen looks stuck.

  5. Open it from another computer

    In a browser on your normal computer, go to http://homeassistant.local:8123. If that does not resolve, use the IP address shown on the Home Assistant console, for example http://192.168.1.50:8123.

    You get the onboarding wizard: create the owner account, name your home, set your location and unit system, and let it find devices on the network. That is the install finished.

First start

Give it an hour before you judge it. On the first day Home Assistant is downloading integrations and building its database, so the interface can feel slow and the CPU can sit high. It settles.

  • Set up backups. Settings → System → Backups. A backup on the same disk protects you from mistakes, not from a dead disk; add a network location or a cloud target when you can.
  • Write down the IP address or give the machine a fixed one in your router, so the address you bookmark keeps working.
  • Wi-Fi on the target machine is set up from the console the first time, not from the browser. Ethernet avoids it entirely.

If it doesn't work

The machine will not boot from the disk

Secure Boot is the usual cause. Go back into the firmware and turn it off. If the disk is not listed at all, check that it is in UEFI mode and that the disk itself is not a 4Kn drive — Home Assistant OS needs 512-byte logical sectors and cannot boot from disks that only offer 4K.

"Error unmounting filesystem" while restoring

You are running the live system from the disk you are trying to overwrite. Boot the USB stick again and choose Try Ubuntu rather than Install Ubuntu. If live Ubuntu has picked up an old swap partition on the target disk, stop that swap partition in Disks first.

The page never loads

Wait the full twenty minutes. Then check the console: if it shows no IP address, the network is the problem — cable, DHCP, or Wi-Fi that was never configured. Try http:// explicitly; a browser that insists on HTTPS will fail against port 8123.
